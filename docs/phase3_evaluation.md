# Phase 3：回答生成・評価結果

## 1. Phase 3の目的

Phase 3では、Phase 2で構築した検索基盤（PostgreSQL + pgvector）の上に、Ollamaを用いた回答生成機能および根拠提示機能を実装し、ローカル完結型RAGチャットボットとして一連のパイプラインを完成させることを目的とした。

また、評価用質問セット（Q01〜Q05）を用いて検索精度（目標：Micro Recall@5 85%以上）および回答生成・根拠提示精度（目標：Q01〜Q05の5問中4問以上の正解）の定量評価を実施し、目標に対する達成状況と現在地・課題を明確化することを目的とした。

---

## 2. 実装した機能

- `search_chunks()` により、質問文に関連する上位チャンクを検索
- `generate_answer()` における2段階生成と厳密な引用検証の実装
  - **第1段階（Fact抽出）**：検索上位チャンクから質問に関連する事実（`fact`）、原文引用（`quote`）、参照元（`reference`）をJSON Schema（Structured Outputs）で抽出
  - **第2段階（回答Claim生成）**：検証済みのFactのみを入力として、箇条書きの主張（`text`）と引用情報を生成
  - **引用・数値検証（`_is_valid_citation` / `_has_unsupported_numbers`）**：`quote` が参照チャンク本文の連続部分文字列として存在するか、また主張文中の数値が当該Claimの引用原文（`quote`）に含まれているかをプログラム側で厳密に検証
- **根拠提示型（原文フォールバック）の実装（`_build_fallback_from_chunks`）**
  - 第1段階で検証済みFactが得られなかった場合、または第2段階で検証済みClaimが0件となった場合、不正確な回答生成を抑止し、検索上位チャンクの原文を要約・言い換え・加工なしでそのまま提示（文書ID・ページ番号・チャンク番号を明記）
- [streamlit_app.py](file:///c:/Users/admin/Documents/rag-chatbot/streamlit_app.py) において、回答本文および参照元（文書ID・ページ番号・チャンク番号）の表示に対応
- 評価スクリプト（[test_evaluation.py](file:///c:/Users/admin/Documents/rag-chatbot/test_evaluation.py)、[test_generation_evaluation.py](file:///c:/Users/admin/Documents/rag-chatbot/test_generation_evaluation.py)）および単体テスト（計15件）の整備

## 3. 評価方法

### 3.1 評価条件

- **対象データ**：`DOC-001`（`data/raw/ipa_dx_report.pdf`、全8ページ・21チャンク）
- **対象質問**：Q01〜Q05の計5問（すべて同一の評価条件で実行）
- **検索条件**：`search_chunks(question, limit=5)` で取得した検索上位5件をそのまま評価に使用（特定チャンクへの絞り込み等は行わない）
- **生成モデル**：Ollama `qwen2.5:3b-instruct`（`temperature=0`）
- **評価基準と目標**：
  - **検索評価（目標：Micro Recall@5 85%以上）**：各質問の正解チャンク（`expected_chunks`）が検索上位5件に含まれる割合（Recall@5）を質問別・Macro平均・Micro平均で算出
  - **回答生成・根拠提示評価（目標：Q01〜Q05の5問中4問以上の正解）**：
    - **回答生成成功**：検証を通過したClaimにより、質問に対する期待情報を正しく網羅し、正しい根拠チャンクを引用して回答できたケース
    - **根拠提示成功**：検証済みFactが得られなかった場合、または検証済みClaimが0件となり、原文フォールバックが発動したケースのうち、検索上位5件に正解チャンクが含まれ、誤情報（ハルシネーション）を出さずに根拠チャンクの原文・文書ID・ページ番号・チャンク番号を正確に提示できたケース（※回答生成成功には含めず別集計とする）
    - **不適切回答**：検証を通過したClaimが生成されたが、期待される結論と異なる内容や不適切な引用となったケース。

### 4.3 原文フォールバックの有効性

今回の評価において、プログラム側の厳密な引用・数値検証と**原文フォールバック（根拠提示型）**を組み合わせたことで、以下の有効性が確認された。

1. **ハルシネーション（根拠のない数値・事実の捏造）の抑止**：Q01・Q02・Q03・Q05の4問において、引用検証や数値検証を通過しなかった不確実な生成結果がユーザーに表示されるのを防ぐことができた。
2. **根拠情報の正確な提示**：フォールバック発動時にも検索上位チャンクの原文を一切加工せず、文書ID（`DOC-001`）・ページ番号・チャンク番号とともに提示することで、ユーザーが正確な一次情報（正解チャンクを含む）を直接確認できる仕組みとして機能した。

## 5. 既知の課題

### 5.1 Q04における回答・引用の問題

Q04（「従業員規模によって、DXの成果が出ている割合にはどのような違いがありますか？」）では、期待される結論は「従業員規模による差は小さい」であり、正解チャンクである `DOC-001` p.2 chunk=1（資料1）が検索1位で取得できていたにもかかわらず、以下の問題が発生した。

- **誤った資料の引用**：検索1位の `DOC-001` p.2 chunk=1（資料1）ではなく、検索2位の `DOC-001` p.3 chunk=1（資料2）を引用した。
- **不適切な結論の生成**：「DXの成果が出ている割合には、従業員規模によって違いがあります[資料2]」「具体的な数値は記載されていません[資料2]」という、本来の期待される結論（「従業員規模による差は小さい」）と異なる不適切な回答を生成した。図表見出し等の表層的な文字列が原文に存在する場合、文字列一致による引用検証だけではこのような誤引用・不適切回答を防ぎきれないことが確認された。

### 5.2 回答生成における課題

- **回答生成成功が0件（5問中4問以上の正解目標に対して未達）**：Q01・Q02・Q03・Q05では厳密な引用・数値検証を通過するClaimが残らず原文フォールバックとなり、Q04では不適切回答となったため、自然文での回答生成成功は5問中0件にとどまった。

### 5.3 検索（Recall@5）における課題

- **複数チャンクに跨る質問での取りこぼし（Micro Recall@5 85%目標に対して未達）**：
  - Q01では `DOC-001` p.1 chunk=2 が上位5件から漏れた（Recall@5 = 50.0%）。
  - Q05では `DOC-001` p.4 chunk=2 が上位5件から漏れ、p.4 chunk=1 と p.7 chunk=2 の2件のみのヒットにとどまった（Recall@5 = 66.7%）。

## 7. Phase 3のまとめと今後の改善方針

### 7.1 Phase 3のまとめ

Phase 3により、文書登録・チャンク分割・Embedding生成・ベクトル検索・2段階回答生成・厳密な引用検証・原文フォールバック・Streamlit UI表示までの一連のRAGパイプラインが動作し、Q01〜Q05の定量評価を完了した。

定量評価の結果、検索精度は **Macro Recall@5：83.3% / Micro Recall@5：75.0%**（目標のMicro Recall@5 85%以上に対して未達）、回答評価は **回答生成成功：0件 / 根拠提示成功：4件 / 不適切回答：1件**（目標の5問中4問以上の回答生成成功に対して未達）となった。一方で、厳密な引用検証と原文フォールバックの導入により、5問中4問においてハルシネーションを防ぎつつ正解チャンクを含む原文と出典（文書ID・ページ番号・チャンク番号）を正確に提示できることを確認した。

### 7.2 今後の改善方針

1. **検索精度の改善（Micro Recall@5 85%以上の達成に向けて）**
   - 複数チャンクが正解となる質問（Q01、Q05）での取りこぼしを防ぐため、チャンク分割サイズ・オーバーラップの見直し、または検索ヒットしたチャンクの前後チャンクを補完する仕組みを検討する。
2. **Q04のような誤引用・不適切回答の防止**
   - 図表タイトルや節見出しのみを根拠としたFact抽出の抑止、および「具体的な数値は記載されていません」といったメタ発言Claimの検証ルール強化を検討する。
3. **回答生成成功率の向上（5問中4問以上の正解達成に向けて）**
   - モデルの引用抽出精度やプロンプト・検証ロジックの改善（またはよりパラメータ数の大きいローカルモデルの検証）により、安全性を維持したまま自然文での回答生成成功率を引き上げる。
